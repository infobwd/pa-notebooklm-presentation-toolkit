# Generic End-to-End Example

> **ตัวอย่างสมมติทั้งหมด — FICTIONAL SAMPLE**  
> ไม่มีบุคคล โรงเรียน ผลสอบ รางวัล หรือนโยบายจริงอยู่ในชุดนี้  
> ใช้เพื่อดูว่าเมื่อกรอก Template ครบแล้ว ไฟล์ปลายทางควรมีหน้าตาอย่างไรเท่านั้น

## Persona สมมติ

- ชื่อ: **นายตัวอย่าง การศึกษา**
- ตำแหน่ง: ผู้อำนวยการสถานศึกษา
- สถานศึกษา: **โรงเรียนตัวอย่างพัฒนา**
- สังกัด: **สำนักงานเขตพื้นที่การศึกษาตัวอย่าง**
- ประเด็นท้าทาย: **การพัฒนาการอ่านเพื่อความเข้าใจด้วย READ Model**
- เวลานำเสนอ: 5 นาที

## ลำดับการเปิดดู

1. `01_profile_example.md` — ข้อมูลตั้งต้น
2. `02_presentation_results_example.md` — WHAT TO SAY
3. `03_visual_storyboard_example.md` — WHAT TO SHOW
4. `04_script_5min_example.md` — HOW TO SAY IT
5. `05_actual_results_example.md` — ตัวอย่าง TARGET/ACTUAL
6. `06_source_manifest_example.md` — เลือก Sources
7. `07_notebooklm_prompts_example.md` — Prompt ที่กรอกแล้ว
8. `08_final_qa_example.md` — QA ก่อน Final

## สิ่งที่ควรสังเกต

- TARGET และ ACTUAL แยกจากกันชัดเจน
- CONTEXT ใช้อธิบายที่มา ไม่ถูกเรียกว่า “ผลสำเร็จ”
- Visual Storyboard ระบุว่าอะไรต้องใช้ภาพจริง
- Script สั้น ไม่พยายามอ่านทุกข้อมูล
- Supporting Systems อยู่หลังผลลัพธ์ ไม่แย่งแกนหลัก
- Source Manifest ไม่โยนเอกสารดิบทุกอย่างเข้า NotebookLM
- Final QA ตรวจทั้งข้อมูล ภาพ เวลา และการปะปนของข้อมูล

## ห้ามทำ

- ห้าม Copy ชื่อ/ตัวเลข/READ Model จากตัวอย่างไปใช้เป็นข้อมูลจริง
- ห้ามนำตัวอย่างนี้เข้า NotebookLM ร่วมกับ Project จริง
- ให้ Copy เฉพาะ “โครงสร้างและวิธีคิด” แล้วแทนด้วยข้อมูลจริงของผู้ใช้
